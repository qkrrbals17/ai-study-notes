
===== ① Prompt Chaining =====
   개요: 1. 정의 2. 수식 3. 예시
   본문: 본문(1. 정의 2. 수식 3. …을 바탕으로 작성)
   검증: PASS
   ⏱ 0.60s | LLM 호출 3회 | 비용 3.0

===== ② Routing =====
   '환불하고 싶어요' → 환불 → 환불 정책 에이전트 (결제 도구 접근)
   '로그인이 안 돼요' → 기술 → 기술 지원 에이전트 (로그 조회 도구)
   '영업시간이 언제예요?' → 일반 → FAQ 응답 (작은 모델)
   ⏱ 0.60s | LLM 호출 3회 | 비용 0.3

===== ③-a Parallelization: Sectioning (코드 리뷰를 관점별 동시 실행) =====
   보안 관점: 문제 1건
   성능 관점: 문제 1건
   가독성 관점: 문제 0건
   테스트 관점: 문제 1건
   ⏱ 0.20s | LLM 호출 4회 | 비용 4.0

===== ③-b Parallelization: Voting (같은 질문 5번 → 다수결) =====
   투표: ['위험', '안전', '안전', '안전', '안전'] → 결론: 안전
   ⏱ 0.20s | LLM 호출 5회 | 비용 5.0

===== ④ Orchestrator-Workers =====
   오케스트레이터가 나눈 작업: ['data_loader.py', 'model.py', 'train.py']
   워커 → data_loader.py 수정 완료
   워커 → model.py 수정 완료
   워커 → train.py 수정 완료
   오케스트레이터 종합: 3개 파일 변경 사항 통합, 테스트 실행 필요
   ⏱ 0.40s | LLM 호출 4회 | 비용 4.0

===== ⑤ Evaluator-Optimizer =====
   반복 0: 'LoRA 설명 초안' → 점수 5/10 - 예시를 더 추가할 것
   반복 1: 'LoRA 설명 초안 +개선' → 점수 7/10 - 예시를 더 추가할 것
   반복 2: 'LoRA 설명 초안 +개선 +개선' → 점수 9/10 OK
   ⏱ 1.00s | LLM 호출 5회 | 비용 5.0

정리: 체이닝=순차·정확, 라우팅=비용절감, 병렬=속도/신뢰도, 오케스트레이터=동적 분해, 평가-최적화=품질 반복개선

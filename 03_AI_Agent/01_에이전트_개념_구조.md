# AI 에이전트 개념과 구조

## 1. 에이전트란?
> **LLM이 스스로 다음 행동을 결정하고, 도구를 사용해 환경과 상호작용하며, 결과를 관찰해 목표를 달성할 때까지 반복하는 시스템**

일반 챗봇: 질문 → 답변 (1회)
에이전트: 목표 → [생각 → 행동(도구) → 관찰] 반복 → 결과

## 2. 핵심 구성 요소
```
            ┌──────────────── 에이전트 ────────────────┐
 사용자 목표 →│  🧠 LLM (두뇌: 추론·결정)                   │
            │  🛠 도구 (검색, 코드 실행, API, 파일, DB)    │
            │  💾 메모리 (대화 기록, 장기 지식)            │
            │  🗺 계획 (작업 분해, 순서 결정)               │
            └──────────────────────────────────────────┘
                         ↕ 행동 / 관찰
                       🌍 환경
```

## 3. 에이전트 루프 (Agent Loop)
```python
messages = [system_prompt, user_goal]
while True:
    response = llm(messages, tools=tools)
    if response.wants_tool:
        result = run_tool(response.tool_name, response.args)   # 행동
        messages += [response, result]                         # 관찰
    else:
        return response.text                                   # 종료
```
본질은 매우 단순하다: **루프 + 도구 + 종료 조건**

## 4. 워크플로우 vs 에이전트
| | 워크플로우 (Workflow) | 에이전트 (Agent) |
|---|---|---|
| 흐름 결정 | 개발자가 코드로 미리 정함 | LLM이 실행 중 동적으로 결정 |
| 예측 가능성 | 높음 | 낮음 |
| 유연성 | 낮음 | 높음 |
| 비용/지연 | 낮음 | 높음 |
| 적합한 문제 | 단계가 명확한 작업 | 단계 수·경로를 미리 알 수 없는 열린 작업 |

**원칙: 가장 단순한 해법부터.** 단일 LLM 호출 → 워크플로우 → 에이전트 순으로 필요할 때만 복잡도를 올린다.

## 5. 자율성 수준
1. 단일 LLM 호출 (분류, 요약)
2. 고정 체인 (A → B → C)
3. 라우터 (LLM이 경로 선택)
4. 도구 호출 루프 에이전트
5. 멀티에이전트 / 장시간 자율 에이전트 (코딩 에이전트, 리서치 에이전트)

## 6. 대표 활용 분야
- **코딩 에이전트**: 코드베이스 탐색, 수정, 테스트 실행, PR 생성
- **리서치 에이전트**: 여러 번 검색·읽기·종합 후 보고서
- **고객 지원**: 주문 조회, 환불 처리 등 도구 연동
- **데이터 분석**: SQL/파이썬 실행으로 분석·시각화
- **컴퓨터/브라우저 사용**: 화면을 보고 클릭·입력

## 7. 에이전트가 어려운 이유
- 오류 누적: 각 단계 성공률 95%라도 20단계면 전체 성공률 ≈ 36%
- 긴 컨텍스트 관리, 비용·지연
- 비결정성 → 테스트·디버깅 어려움
- 보안 (도구 권한, 프롬프트 인젝션)
→ 그래서 **좋은 도구 설계, 평가, 가드레일, 사람 확인(Human-in-the-loop)**이 중요

### 📝 실습 후 정리

- 에이전트의 본질은 '모델 호출 → 도구 실행 → 결과를 대화에 추가'의 반복 + 종료 조건이라는 것을 30줄 루프로 확인.
- 도구 오류(없는 도시)도 예외로 죽이지 않고 '관찰'로 돌려주면 모델이 대처할 수 있음.
- 같은 행동만 반복하는 모델도 max_steps가 막아줌 → 비용 폭주 방지의 최소 장치.

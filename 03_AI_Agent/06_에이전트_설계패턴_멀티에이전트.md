# 에이전트 설계 패턴 & 멀티 에이전트

## 1. 기본 빌딩 블록: Augmented LLM
LLM + 검색 + 도구 + 메모리. 모든 패턴은 이것의 조합.

## 2. 워크플로우 패턴 (흐름을 코드로 정의)

### ① 프롬프트 체이닝 (Prompt Chaining)
```
입력 → LLM1(개요 작성) → [검증 게이트] → LLM2(본문 작성) → LLM3(번역) → 출력
```
작업이 고정된 하위 단계로 깔끔하게 나뉠 때. 정확도↑ 대신 지연↑

### ② 라우팅 (Routing)
```
입력 → 분류 LLM ─┬─▶ 환불 처리 흐름
                ├─▶ 기술 지원 흐름
                └─▶ 일반 문의 (작은 모델)
```
입력 유형별로 특화된 처리. 쉬운 질문은 작고 싼 모델로 보내 비용 절감

### ③ 병렬화 (Parallelization)
- **Sectioning**: 독립 하위 작업을 동시에 (예: 코드 리뷰 – 보안/성능/스타일 각각)
- **Voting**: 같은 작업을 여러 번 → 다수결/종합 (신뢰도↑)

### ④ 오케스트레이터-워커 (Orchestrator-Workers)
```
          ┌─▶ 워커1 (파일 A 수정)
오케스트레이터 ─┼─▶ 워커2 (파일 B 수정)     → 결과 종합
 (동적 분해)  └─▶ 워커3 (테스트 작성)
```
하위 작업을 **미리 알 수 없을 때** 중앙 LLM이 동적으로 나눠 위임

### ⑤ 평가자-최적화자 (Evaluator-Optimizer)
```
생성 LLM ⇄ 평가 LLM (피드백) … 기준 통과까지 반복
```
명확한 평가 기준이 있고 반복 개선이 효과적일 때 (번역, 글쓰기, 검색 리서치)

## 3. 자율 에이전트
도구 호출 루프로 스스로 경로를 결정. 환경으로부터의 피드백(실행 결과)을 매 단계 확인하는 것이 핵심. 샌드박스·가드레일·중단 조건 필수.

## 4. 멀티 에이전트 (Multi-Agent)

### 구조 유형
| 구조 | 설명 | 예 |
|---|---|---|
| **수퍼바이저(계층형)** | 리더 에이전트가 하위 에이전트에 위임·종합 | 리서치 리드 + 검색 서브에이전트들 |
| **핸드오프(순차)** | 담당 에이전트가 다음 에이전트로 대화 넘김 | 접수 → 결제 → 배송 상담 |
| **네트워크/협업** | 에이전트들이 서로 메시지 교환 | 토론, 역할극 시뮬레이션 |
| **블랙보드** | 공유 작업 공간에 기록·참조 | 공동 문서 작성 |

### 장점
- **컨텍스트 분리**: 서브에이전트가 각자 깨끗한 컨텍스트로 탐색 → 요약만 리더에게
- 병렬 처리로 속도↑ (넓은 리서치에 특히 효과적)
- 역할별 전문 프롬프트·도구

### 단점
- 토큰 비용이 크게 증가
- 에이전트 간 정보 손실·중복 작업·조율 실패
- 디버깅 어려움
- 강하게 결합된 작업(같은 코드를 동시에 수정 등)엔 부적합

### 설계 팁
- 위임할 때 **목표, 출력 형식, 사용할 도구, 범위/경계**를 명확히
- 작업 난이도에 따라 서브에이전트 수 조절
- 최종 결과는 리더가 검증
- **단일 에이전트로 충분한지 먼저 확인**

## 5. Human-in-the-loop
- 승인 지점: 결제, 메시지 전송, 삭제, 배포 등 되돌릴 수 없는 행동 전
- 불확실할 때 질문하기
- 중간 체크포인트에서 사람이 방향 수정

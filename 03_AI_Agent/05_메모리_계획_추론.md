# 메모리 · 계획 · 추론 (Memory, Planning, Reasoning)

## 1. 추론-행동 패턴

### ReAct (Reason + Act)
생각(Thought) → 행동(Action) → 관찰(Observation)을 번갈아 반복
```
Thought: 서울 인구를 알아야 한다
Action: search("서울 인구 2026")
Observation: 약 9xx만 명 ...
Thought: 이제 부산과 비교하자
Action: search("부산 인구")
...
Final Answer: ...
```
- 장점: 단순, 유연, 해석 가능 / 단점: 장기 계획이 약하고 단계가 많아지면 헤맴
- 현대 Tool-calling 에이전트 루프의 사실상 기본형

### Plan-and-Execute
1. **Planner**가 전체 계획(단계 목록)을 먼저 작성
2. **Executor**가 단계를 하나씩 실행
3. 필요 시 **Re-plan**
- 긴 작업에 유리, 진행 상황 추적 쉬움 (TODO 리스트 방식)

### Reflection / Self-critique
- 결과물을 스스로 평가·비판 → 수정 (Reflexion)
- **Evaluator-Optimizer**: 생성자 LLM + 평가자 LLM 반복
- 외부 검증(테스트 실행, 컴파일, 계산)이 가능하면 **자기 평가보다 훨씬 신뢰도 높음**

### 탐색 기반
- Tree of Thoughts: 여러 추론 경로를 트리로 탐색, 평가 후 선택
- 비용이 크므로 정답 검증이 가능한 문제에 적합

### 추론(Thinking) 모델
최근 모델은 답하기 전에 내부적으로 긴 사고를 수행 → 복잡한 계획·코딩·수학에서 강함. 에이전트에서 도구 호출 사이사이에도 사고를 활용할 수 있음.

## 2. 메모리 (Memory)

| 종류 | 사람 비유 | 구현 |
|---|---|---|
| **단기(작업) 메모리** | 지금 머릿속 | 컨텍스트 창 안의 대화·도구 결과 |
| **장기 메모리 – 의미적** | 사실 지식 | 벡터DB/KV 저장소의 사용자 정보·선호 |
| **장기 메모리 – 일화적** | 과거 경험 | 이전 작업 기록, 성공/실패 사례 |
| **절차적 메모리** | 방법·습관 | 시스템 프롬프트, 스킬 파일, 학습된 규칙 |

### 컨텍스트 관리 기법
- **슬라이딩 윈도우**: 최근 N개 메시지만 유지
- **요약(Compaction)**: 오래된 대화를 요약해 대체
- **도구 결과 정리**: 이미 처리된 긴 결과는 제거·축약
- **외부 노트(Scratchpad)**: 에이전트가 파일에 진행 상황·결정 사항을 기록하고 필요할 때 다시 읽음
- **서브에이전트로 위임**: 탐색은 별도 컨텍스트에서 하고 요약만 돌려받음

### 장기 메모리 설계 질문
- 무엇을 저장할까? (사실, 선호, 작업 결과)
- 언제 쓸까? (매 턴 자동 vs 명시적 "기억해")
- 어떻게 꺼낼까? (검색, 항상 주입)
- 오래되거나 틀린 기억은 어떻게 갱신·삭제?
- 개인정보 보호와 사용자 통제

## 3. 작업 분해 (Task Decomposition)
- 큰 목표 → 검증 가능한 작은 하위 작업
- 각 하위 작업에 **완료 기준** 정의
- 의존성 없는 작업은 병렬 실행

## 4. 실패 모드와 대응
| 실패 | 대응 |
|---|---|
| 같은 행동 무한 반복 | 최대 단계 수, 반복 감지 |
| 목표 이탈 | 계획/TODO를 컨텍스트에 유지, 주기적 목표 재확인 |
| 잘못된 가정 위에 계속 진행 | 중간 검증, 불확실하면 사용자에게 질문 |
| 컨텍스트 초과 | 요약, 외부 메모리, 서브에이전트 |
| 조기 종료("다 했어요") | 명확한 완료 조건, 검증 단계 강제 |

- ReAct 형식을 파싱하고, 형식 오류도 관찰로 돌려주면 다음 단계에서 복구됨.
- 토큰 예산을 넘으면 오래된 메시지 10개를 요약 1개로 압축(compaction)하고 최근 대화는 원문 유지.
- 장기 메모리는 저장→검색→주입 구조. Plan-and-Execute에서 실패한 단계를 수정(re-plan)해 전체 계획 완료.

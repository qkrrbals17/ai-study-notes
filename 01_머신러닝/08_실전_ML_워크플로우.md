# 실전 ML 프로젝트 워크플로우

## 1. 전체 흐름
```
문제 정의 → 데이터 수집 → EDA → 전처리/특성공학 → 베이스라인
   → 모델 실험/튜닝 → 오류 분석 → 최종 평가 → 배포 → 모니터링 → (반복)
```

## 2. 단계별 체크포인트
1. **문제 정의**: 비즈니스 목표를 ML 문제(회귀/분류/랭킹)로 변환, 성공 지표·기준선 정의
2. **데이터**: 출처, 라벨 품질, 기간, 편향 여부 확인
3. **분할 먼저**: 테스트 세트를 가장 먼저 떼어 놓기 (시간/그룹 고려)
4. **베이스라인**: 평균/최빈값 예측 → 로지스틱/선형 → GBM 순으로
5. **실험 관리**: 시드 고정, 설정·점수 기록 (MLflow, Weights & Biases)
6. **오류 분석**: 틀린 샘플을 직접 보고 패턴 찾기 → 특성/데이터 개선
7. **최종 평가**: 테스트 세트는 단 한 번
8. **배포**: 모델 직렬화(joblib, ONNX), API 서빙(FastAPI), 배치 예측
9. **모니터링**: 데이터 드리프트, 개념 드리프트, 성능 저하 감지 → 재학습

## 3. 모델 선택 가이드 (정형 데이터)
```
데이터 작음 & 해석 중요 → 로지스틱/선형 회귀, 결정트리
기본 고성능 → LightGBM / XGBoost / CatBoost
범주형 많음 → CatBoost
텍스트/이미지/음성 → 딥러닝 (02_딥러닝 폴더)
```

## 4. MLOps 입문 키워드
- 실험 추적: MLflow, W&B
- 데이터/모델 버전 관리: DVC, 모델 레지스트리
- 파이프라인 오케스트레이션: Airflow, Prefect, Kubeflow
- 피처 스토어: Feast
- 서빙: FastAPI, BentoML, Triton
- 모니터링: Evidently 등

## 5. 흔한 실수 Top 7
1. 데이터 누수 (전처리를 분할 전에 fit)
2. 테스트 세트로 튜닝
3. 불균형 데이터에 Accuracy 사용
4. 시계열을 무작위로 분할
5. 베이스라인 없이 복잡한 모델부터 시작
6. 랜덤 시드·환경 미고정으로 재현 불가
7. 배포 후 모니터링 부재

### 📝 실습 후 정리

- 데이터가 작으면(353건) 로지스틱 회귀(CV AUC 0.862)가 RF·GBM보다 나았음 → 항상 단순 모델부터 비교.
- CV AUC 0.868 vs 최종 test AUC 0.838: 테스트가 약간 낮은 건 정상, 테스트는 마지막에 한 번만 사용.
- 오류 분석: 틀린 샘플은 bmi·s5가 경계 근처 → 다음 개선 방향(특성 추가/임계값)을 찾는 근거가 됨. 모델을 joblib로 저장해 예측 함수로 감쌈.
